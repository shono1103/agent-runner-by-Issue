## テスト定義

### ジョブログからのフェーズ実行確認

- ジョブのログ (`jobStore.appendLog`/`jobStore.setPhase` で記録される内容) から、以下の各フェーズが実際に実行されたことを個別に確認できること
  - 要件定義+テストのラフ作成が行われたことを示すログ
  - 差分が複数コミットに分割されたことを示すログ (コミット数が2以上であること、またはコミットごとの要約が記録されていること)
  - CI通過確認が試みられたことを示すログ
  - コミットごとのレビューが行われたことを示すログ
  - ブランチdiff全体のレビューが行われたことを示すログ
- 上記いずれかのフェーズが欠落した場合、ジョブのログからその欠落を検出できること (フェーズが存在しないことを「ログに記録が無い」として判定できること)

### コミットメッセージの5W1H検証

- 生成された各commitメッセージに、Who (誰が) / What (何を) / When (いつ) / Where (どこで) / Why (なぜ) / How (どうやって) に相当する要素が文面として含まれていること
- 5W1Hのいずれかの要素が欠落しているcommitメッセージを、要件を満たさないものとして検出できること

### PRコメントの検証

- コミットレビュー/ブランチdiffレビューで見つかった懸念事項が、生成されたPRへの指摘コメントとして投稿されていること
- 懸念が0件だった場合 (レビューで問題が見つからなかった場合) は、指摘コメントが投稿されないことを許容すること (「懸念がある場合のみ残す」の解釈とする)

### 既存動作の非リグレッション

- 既存の `assertSafeDiff` によるセーフティチェックが引き続き機能し、禁止パス (`.github/workflows/` 等) への変更がある場合はジョブが `failed` になること
- 既存の `IMPLEMENT_DISALLOWED_TOOLS` (`git push`/`git remote`/`gh`/`curl`/`wget` 禁止) が引き続き有効であること
- ワークフロー導入後も `POST /create-pr` の外部インターフェース・レスポンス形式が変更されていないこと

### 手動確認 (E2E)

1. 要件定義/アーキテクチャ定義/テスト定義が揃ったissueに対してPR作成ジョブを実行する
2. ジョブのログに、ラフ実装 → コミット分割 → CI確認 → コミットレビュー → ブランチdiffレビューの各フェーズが順に記録されていることを確認する
3. 生成されたブランチのコミット履歴が複数コミットに分割されており、各コミットメッセージに5W1Hの要素が含まれていることを確認する
4. 生成されたPRに、レビューで見つかった懸念事項が指摘コメントとして残っていることを確認する (懸念が無ければ0件でよい)
5. 既存の `IMPLEMENT_DISALLOWED_TOOLS` に該当する操作 (git push/gh等) がジョブ内で実行されていないことを確認する
