## 要件定義

### 背景

現在issueには「タスク」用途 (要件定義 / システムアーキテクチャ定義 / テスト定義の3コメントを付与して claude cli で変換する運用) しか想定されていない。#1 では、これに加えて「バグ報告」「機能要望」の2種類のissueを扱えるようにしたい。本issueはその前段として、3種類のissueをGitHub上でテンプレートから作成できるようにし、かつ webhook / userscript がその種類を機械的に判別できる状態を作る。

### 要件

1. GitHubのissue作成画面から、以下3種類のテンプレートを選択できること
   - バグ報告用テンプレート
   - 機能要望用テンプレート
   - タスク用テンプレート (既存の運用に対応するもの)
2. バグ報告用テンプレートは、最低限「再現手順」「期待する動作」「実際の動作」を記入する項目を持つこと
3. 機能要望用テンプレートは、最低限「実現したいこと」「背景・目的」を記入する項目を持つこと
4. タスク用テンプレートは、これまでuserscriptの「フォーマット作成」ボタンが担っていた3コメント (要件定義 / システムアーキテクチャ定義 / テスト定義) の投稿を前提とした運用説明を記載すること。テンプレート自体が3コメントを自動投稿するわけではない
5. テンプレートから作成されたissueは、種類 (バグ報告 / 機能要望 / タスク) を自動的に区別できる目印を持つこと。目印はissue本文の書き換えやコメント追加によって失われない手段であること
6. userscriptは、開いているissueページからこの目印を読み取り、issueの種類を判定できること。判定できない場合 (目印がない、テンプレート導入前の既存issueなど) は「タスク」として扱うこと (後方互換)
7. 既存の「タスク」issue (テンプレート導入前に作成されたもの) の運用が壊れないこと

### 非機能要件

- テンプレート追加はissue作成時の入力・属性に影響するのみで、webhookサーバーのAPIやジョブ実行ロジックには変更を加えない (種類判別ロジックの追加を除く)
